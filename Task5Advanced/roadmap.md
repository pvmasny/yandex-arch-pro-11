# Стратегический роадмап внедрения Data Mesh

### Матрица ответственности (RACI)

| Роль / Активность | Data Product Owner | Data Engineer | BI-аналитик | Центральная команда |
|-------------------|--------------------|---------------|-------------|---------------------|
| Определение Data Product | R | C | C | I |
| Разработка пайплайнов | A | R | C | C |
| Обеспечение качества данных | A | R | I | C |
| Создание витрин и дашбордов | C | C | R | I |
| Публикация в каталог данных | A | R | C | C |
| Политики безопасности | C | C | I | R |
| Инфраструктура | I | C | I | R |

*R — Responsible (исполняет), A — Accountable (отвечает), C — Consult (консультирует), I — Inform (информируется)*


## Стратегический роадмап внедрения Data Mesh
## Этап 1: Пилот (0-6 месяцев)

### Цели и задачи

| Цель | Задачи | KPI успеха |
|------|--------|------------|
| Доказать ценность Data Mesh | Выбрать пилотный домен, создать 2-3 Data Product, внедрить self-service | Сокращение времени получения отчёта с часов до минут |
| Сформировать команды | Назначить Data Product Owner, нанять Data Engineers, обучить BI-аналитиков | Сформированы кросс-функциональные команды |
| Создать инфраструктуру | Развернуть Data Catalog, настроить CI/CD, внедрить стандарты | Data Catalog доступен, 100% пайплайнов в CI/CD |

### Выбор пилотного домена

**Рекомендуемый пилот: Домен «Финтех» (Кредитный контекст)**

| Критерий | Обоснование |
|----------|-------------|
| **Высокая бизнес-ценность** | Кредитный скоринг и отчётность критичны для бизнеса |
| **Изолированность** | Меньше зависимостей от других доменов |
| **Готовность данных** | Данные уже структурированы, есть чёткие метрики |
| **Возможность быстрой победы** | Self-service BI для кредитного портфеля даст быстрый эффект |

### Пилотные Data Products

| Data Product | Владелец | Источники | Потребители | Метрики качества |
|--------------|----------|-----------|-------------|------------------|
| **Кредитный портфель** | Data Product Owner (Финтех) | CreditApplication, CreditAgreement | Аналитика, Риск-менеджмент | Актуальность < 1 мин, полнота 100% |
| **Платёжная аналитика** | Data Product Owner (Финтех) | Transaction, PaymentOrder | Финансовый департамент | Актуальность < 5 сек, точность 99.99% |
| **Скоринг-метрики** | Data Product Owner (Финтех) | CreditScore, RiskAssessment | Кредитный комитет | Доступность 99.9% |

### Ключевые активности этапа

| Активность | Срок | Ответственный | Результат |
|------------|------|---------------|-----------|
| Выбор пилотного домена | Месяц 1 | CTO, Data Platform Architect | Утверждён пилотный домен |
| Формирование команды | Месяц 1 | HR, Data Product Owner | Команда укомплектована |
| Развёртывание Data Catalog | Месяц 1-2 | Data Platform Architect | OpenMetadata/DataHub в pilot |
| Создание 1-го Data Product | Месяц 2-3 | Data Engineer, BI-аналитик | «Кредитный портфель» доступен |
| Создание 2-го Data Product | Месяц 3-4 | Data Engineer, BI-аналитик | «Платёжная аналитика» доступна |
| Внедрение self-service | Месяц 4-5 | BI-аналитик, Data Engineer | Портал самообслуживания работает |
| Оценка и ретроспектива | Месяц 6 | Все участники | Решение о масштабировании |

### Привязка к бизнес-целям

| Бизнес-цель | Вклад этапа |
|-------------|-------------|
| **Снижение времени формирования отчётности** | Self-service BI сокращает время с часов до минут |
| **Подготовка к масштабированию** | Отработаны процессы, стандарты, инструменты |
| **Снижение зависимости от DWH** | Пилотные Data Products используют Kafka и ClickHouse |


## Этап 2: Масштабирование (6-18 месяцев)

### Цели и задачи

| Цель | Задачи | KPI успеха |
|------|--------|------------|
| Масштабировать на все домены | Внедрить Data Mesh в Клиники, ИИ, Головной офис | Все 4 домена работают по Data Mesh |
| Формализовать Data Products | Описать все Data Products в каталоге | 100% критических данных в каталоге |
| Внедрить мониторинг качества | Автоматический мониторинг SLA, качества, lineage | Метрики качества доступны в реальном времени |

### Пилотные Data Products по доменам

**Домен «Клиники»**

| Data Product | Описание | Потребители |
|--------------|----------|-------------|
| **Пациентский профиль (PatientProfile)** | Пациенты, контакты, согласия | Аналитика, Кредитный контекст |
| **Инвентаризация (Inventory)** | Остатки, движения, пороги | Склад, Закупки |
| **Персонал (Staff)** | Сотрудники, графики, загрузка | HR, Аналитика |
| **Эпизоды лечения (Episode)** | Обезличенные метрики (без диагнозов) | Аналитика |

**Домен «ИИ-сервисы»**

| Data Product | Описание | Потребители |
|--------------|----------|-------------|
| **Метрики ИИ (AIMetrics)** | Количество анализов, время обработки, загрузка | Аналитика, DevOps |
| **Результаты анализов (AnalysisResults)** | ТОЛЬКО для медицинского контекста (не в аналитику) | Медицинский контекст |
| **Монетизация ИИ (AIMonetization)** | Подписки, использование, billing | Финансовый департамент |

**Домен «Головной офис»**

| Data Product | Описание | Потребители |
|--------------|----------|-------------|
| **Корпоративные витрины (CorporateMarts)** | Агрегированные данные из всех доменов | Руководство, Регуляторы |
| **Отчёты (Reports)** | Шаблоны, расписания, экспорт | Бизнес-пользователи |
| **Метаданные (Metadata)** | Глоссарий, lineage, политики доступа | Все домены |

### Ключевые активности этапа

| Активность | Срок | Ответственный | Результат |
|------------|------|---------------|-----------|
| Найм Data Product Owners для всех доменов | Месяц 6-7 | HR, CTO | 4 DPO назначены |
| Формирование команд Data Engineers | Месяц 6-8 | HR, DPO | 8-12 Data Engineers |
| Создание Data Products в Клиниках | Месяц 6-10 | Data Engineer, BI-аналитик | 4 Data Products |
| Создание Data Products в ИИ | Месяц 8-12 | Data Engineer, ML Engineer | 3 Data Products |
| Создание Data Products в Головном офисе | Месяц 12-18 | Data Engineer, BI-аналитик | 3 Data Products |
| Внедрение Data Catalog в production | Месяц 9-12 | Data Platform Architect | Каталог данных доступен всем |
| Настройка мониторинга качества | Месяц 12-15 | Data Platform Architect, Data Engineer | Дашборды качества |

### Привязка к бизнес-целям

| Бизнес-цель | Вклад этапа |
|-------------|-------------|
| **Масштабирование по продуктам** | Каждый домен независимо развивает Data Products |
| **Скорость вывода новых продуктов** | Новый сервис = новые Data Products, без ожидания DWH |
| **Самообслуживание** | BI-аналитики сами находят и используют данные через каталог |


## Этап 3: Поддержка и эволюция (18-36 месяцев)

### Цели и задачи

| Цель | Задачи | KPI успеха |
|------|--------|------------|
| Автоматизация качества | Внедрить Data Observability, автоматические тесты, anomaly detection | 95% инцидентов выявляются автоматически |
| Data Product Marketplace | Создать внутренний маркетплейс Data Products | 50+ Data Products доступны |
| ML Ops для моделей | Внедрить MLOps для ИИ-моделей как Data Products | ML модели имеют CI/CD и мониторинг |
| Автоматический lineage | Построение lineage из метаданных | 100% lineage автоматизировано |

### Ключевые активности этапа

| Активность | Срок | Ответственный | Результат |
|------------|------|---------------|-----------|
| Data Observability | Месяц 18-24 | Data Platform Architect | Anomaly detection, SLI/SLO |
| Data Product Marketplace | Месяц 24-30 | Data Catalog Manager | Внутренний маркетплейс |
| MLOps для моделей | Месяц 24-30 | ML Engineer, Data Engineer | ML модели как Data Products |
| Автоматический lineage | Месяц 30-36 | Data Platform Architect | Линейка данных автоматическая |
| Data Mesh Maturity Assessment | Месяц 36 | Все участники | Оценка зрелости, план на следующий период |

### Привязка к бизнес-целям

| Бизнес-цель | Вклад этапа |
|-------------|-------------|
| **Слабосвязанная событийная платформа** | Data Mesh полностью интегрирован с EDA |
| **Монетизация ИИ-функций** | ИИ-модели как Data Products для внешних партнёров |
| **Выход в новые регионы** | Data Mesh позволяет быстро развернуть домены в новых регионах |
