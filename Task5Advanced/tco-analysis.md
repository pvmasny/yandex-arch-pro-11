
# Методология расчёта
Для оценки экономической эффективности перехода на целевую архитектуру выполнен сравнительный анализ совокупной стоимости владения (TCO) на горизонте 3 лет с учётом следующих ключевых факторов:

## Допущения
- Ежегодный рост объёмов данных — 40% (согласно ТЗ: «увеличение количества источников и событий»)
- Рост числа пользователей отчётности — 30% ежегодно (пропорционально росту данных)
- Индексация заработной платы — 5% ежегодно
- Индексация лицензий — 3% ежегодно (по условиям вендоров)
- Усложнение ручной отчётности — рост времени на формирование отчётов 20% ежегодно для As-Is
- Self-Service BI — в целевой архитектуре время аналитиков не растёт

## Статьи затрат включают
- Инфраструктура — CAPEX на оборудование, модернизация, колокация, энергопотребление (As-Is); облачные ресурсы Yandex Cloud с CVoS (To-Be)
- Лицензии — проприетарное ПО (Microsoft, PowerBuilder) в As-Is; Open Source в To-Be
- Персонал — администраторы, инженеры, разработчики с учётом изменения штата
- Миграционные затраты — единоразовые инвестиции в консалтинг, архитектуру и обучение
- Время аналитиков — стоимость рабочего времени на формирование отчётов

# Заключение
1. Динамика затрат

- В 1-й и 2-й годы целевая архитектура дороже текущей на 11,7 млн ₽ и 3,8 млн ₽ соответственно за счёт инвестиций в миграцию и более высокой стоимости облачной инфраструктуры
- В 3-й год происходит перелом: целевая архитектура становится дешевле текущей на 985 981 ₽
- Накопленная разница за 3 года составляет 22,5 млн ₽ в пользу текущей архитектуры, но эта разница сокращается с каждым годом

2. Причины перелома в 3-м году

В текущей архитектуре затраты растут экспоненциально:

- Лицензии Power BI увеличиваются на 30% ежегодно из-за роста числа пользователей
- Время аналитиков растёт на 20% ежегодно из-за усложнения данных (требуется увеличение штата)
- Инфраструктура требует регулярного расширения (CAPEX на новое оборудование)

В целевой архитектуре:
- Self-Service BI позволяет не увеличивать штат аналитиков
- Open Source даёт нулевые лицензионные затраты
- Object Storage обеспечивает дешёвое масштабирование хранения

3. Окупаемость и долгосрочный эффект
- Точка безубыточности достигается в конце 3-го года
- Начиная с 4-го года, при сохранении темпа роста 40% ежегодно, экономия составит 6-15 млн ₽ в год
- Прогнозируемая окупаемость инвестиций (8 млн ₽) — 3,5 года

4. Ключевые выводы
- При отсутствии роста объёмов данных трансформация экономически нецелесообразна
- При заявленном росте 40% ежегодно целевая архитектура не только окупается, но и начинает приносить значительную экономию с 4-го года
- Self-Service BI является критическим фактором экономии, позволяя не масштабировать штат аналитиков пропорционально росту данных
- Использование Yandex Cloud с механизмом резервирования (CVoS) позволяет снизить облачные затраты на 20-25% по сравнению с потреблением по запросу

## Рекомендация
Трансформация экономически обоснована при условии сохранения или увеличения заявленных темпов роста бизнеса. Рекомендуется утвердить переход на целевую архитектуру с prioritзацией внедрения Self-Service BI как ключевого фактора экономии.
