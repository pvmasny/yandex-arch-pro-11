# Архитектурные паттерны

|Паттерн	                        |Статус	    |Обоснование
|-----------------------------------|-----------|------------
Event-Driven Architecture (EDA)     |Adopt   	|Основной архитектурный стиль. Обеспечивает слабую связанность доменов, асинхронность и масштабируемость. Позволяет строить систему вокруг событий, что критически важно для интеграции медицинских, финансовых и ИИ-сервисов.|
|Domain-Driven Design (DDD)	        |Adopt	    |Используется для выделения bounded contexts (Клиники, Финтех, ИИ, Головной офис). Обеспечивает чёткие границы доменов и единый язык между бизнесом и разработкой.|
|Data Mesh	                        |Trial	|Подход к децентрализации данных. Каждый домен владеет своими данными и предоставляет их как продукт. Снижает зависимость от центрального DWH, что критично для изоляции медицинских данных.
|CQRS |Adopt	|Разделение команд (запись) и запросов (чтение). Оптимизирует производительность витрин данных и потоковой обработки.
|Saga Pattern	|Adopt	|Управление распределёнными транзакциями в событийной архитектуре. Обеспечивает согласованность данных между доменами (например, кредитный конвейер).
|Anti-Corruption Layer (ACL)	|Adopt	|Изоляция легаси-систем от новых сервисов. Позволяет контролировать миграцию данных и трансформацию протоколов.
|Self-Service BI	|Adopt	|Портал самообслуживания для бизнес-пользователей. Ускоряет получение отчётности, снижает нагрузку на ИТ.
|API Gateway| Adopt | Единая точка входа API 

# Инфраструктура и оркестрация
|Технология	|Статус |	Обоснование
|-----------------------------------|-----------|------------
|K8s	|	Adopt	| Стандарт для оркестрации контейнеров, обеспечивает масштабирование, отказоустойчивость и управление жизненным циклом сервисов.
|Docker	|	Adopt	|Базовый инструмент для упаковки и доставки микросервисов в воспроизводимой среде.
|Terraform	|	Adopt	|Декларативное управление инфраструктурой как кодом, поддерживает мультиоблачные сценарии.
|Helm		|Adopt	|Упрощает развёртывание и обновление приложений в Kubernetes через чарты.
|Service Mesh (Istio/Linkerd)	|	Assess	|Улучшает наблюдаемость, безопасность и маршрутизацию трафика между сервисами, но добавляет сложность.

# Обработка данных и событий
|Технология|	Статус	|Обоснование
|-----------------------------------|-----------|------------
|Apache Kafka |Adopt	|Надёжная, масштабируемая шина для публикации и подписки на события (например, PatientRegistered).
|Debezium	|	Trial	|Захват изменений данных из БД (например, PostgreSQL) и трансляция их в Kafka для реактивных сценариев.
|Apache Flink	|Trial	|Обработка сложных событий (CEP), агрегация и аналитика в реальном времени на основе потоков из Kafka.


# Хранение данных
|Технология|	Статус	|Обоснование
|-----------------------------------|-----------|------------
|PostgreSQL	|	Adopt	|Основная реляционная БД для агрегатов (Patient, Episode). Поддерживает JSON, транзакции и репликацию.|
|Redis	Кэш	|Adopt	|Кэш для быстрого доступа к часто используемым данным (профили пациентов, справочники).
|ClickHouse	|Adopt	|Витрины данных для аналитики. Колоночное хранение, молниеносные запросы. Замена Power BI и тяжелых отчётов из DWH.
|Microsoft SQL Server 2008	|Hold	|Легаси DWH. Активно вытесняется, новые разработки не ведутся. Поддержка только для исторических данных.
